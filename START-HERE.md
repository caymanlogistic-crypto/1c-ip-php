## Подготовка локального запуска

Используй существующие PHP C:/php/php.exe и MySQL 127.0.0.1:43061. Зависимости установи по composer.lock в vendor своего worktree без обновления версий.

Для параллельных запусков нужны:

- Разные свободные порты, например 8871 и 8872. Чужой процесс не останавливать.
- Разные тестовые схемы ipphp_task_<id> и одноимённые пользователи с правами только на свою схему. Суффикс: 1–20 строчных латинских букв, цифр или _. Общую серверную БД и изменяемую копию другого агента не подключать.
- Свои .local, runtime/sessions, private, storage, uploads, документы, artifacts и профиль браузера. Не связывай изменяемые каталоги с чужим worktree. Launcher вычисляет отдельное имя cookie от пути и порта; разные порты сами по себе cookie не разделяют.

Когда нужны бизнес-проверки, подготовь разрешённую независимую копию: согласованный тестовый снимок → новая пустая схема существующим bin/restore.php → реальная сверка копии. Restore требует APP_DB_CONFIG_FILE целевой схемы, SQL и его hash receipt; поверх таблиц не восстанавливает. Миграции автоматически не запускать. Нужные документы копировать со сверкой хешей. Сессии/PID, активные профили отправок и допуски не переносить; очереди не проигрывать.

В .local/database.php храни реквизиты своей схемы. Пример .local/runtime-settings.json (путь, имя и порт замени действительными):

Результат сверки сохраняется в .local/copy-verification.json: database, exact_copy_before_login: true, isolated_test_data: true, app_root и доказательства проверки. Флаги записываются после фактической проверки, не для обхода preflight. Сохранённая T001 на 8766 — исторический кандидат, её БД новыми worktree не используется.

## Запуск и остановка

Из своего worktree, PowerShell 7:

```powershell
./Start-Local.ps1 -Port 8871 -Plan
./Start-Local.ps1 -Port 8871 -NoBrowser
# Или ./Start.cmd -Port 8871 — открыть свой профиль браузера.
# URL: http://127.0.0.1:8871/login
./Stop-Local.ps1
```

Start проверяет корень/project_id/порт, PHP, фактическую БД, ограниченные grants и receipt копии. Он не создаёт/не восстанавливает БД и не перезапускает MySQL. -Plan работает без приватной конфигурации и ничего не запускает. Stop проверяет PID, время, PHP, корень и порт; останавливает только свой процесс. Не копировать runtime.json и не удалять работающий worktree.

## Проверка и публикация

### Локальная проверка подключения MAX

После подготовки и полной сверки своей тестовой БД, установки lock-зависимостей и переноса разрешённого существующего MAX vault в собственный `private/integrations`:

```powershell
$env:APP_DB_CONFIG_FILE=Join-Path $PWD '.local/database.php'
C:/php/php.exe bin/max-local-read-setup.php --enable
./Start-Local.ps1 -Port <свой_порт> -NoBrowser
```

Команда создаёт только приватный `.local/max-read-access.json`, привязанный к worktree/БД/revision/группам/hash vault. Она требует включённый существующий профиль с разрешёнными группами и не меняет его. На Windows используется существующий проверенный локальный trust bundle `.local/certs/windows-trusted-roots.pem`; TLS verification сохраняется. В `/max` пользователь с правами `messaging.read`, `messaging.send` и редактированием страницы нажимает «Проверить подключение»: проверяются токен и членство бота во всех активных разрешённых группах, результат сохраняется в журнале. Повтор того же request_key не обращается к MAX повторно. Pending другой операции блокирует проверку до сверки результата.

По умолчанию общий внешний допуск, отправки, AutoMAX и старые очереди остаются выключены. По конкретному разрешению владельца ручную отправку только в единственную активную разрешённую группу «ТЕСТОВАЯ» включает `bin/max-local-read-setup.php --enable-manual-send --refresh`. В этой локальной копии владелец разрешил такую отправку; общий внешний gate и AutoMAX остаются выключены. Старые попытки не повторяются, новый запрос из формы имеет собственный ключ. Сохранение прежних полей MAX не меняет revision. Для уже возникшего рассогласования версия связывается заново только явным `--rebind-unchanged-profile`: команда требует точного совпадения токена и адресата с исходным сохранённым approved profile и сохраняет приватный резерв vault/marker. Ошибки до входа в транспорт записываются как failed, а не uncertain. Изменение revision/vault/групп прекращает действие допуска; после проверки новых настроек приватный marker следует подготовить заново. Кандидат MAX-LOCAL использует `http://127.0.0.1:8877/max`, отдельный worktree `1c-ip-max-local`, БД `ipphp_task_max_local`.

Покажи пользователю зафиксированный локальный commit, URL/роль, короткий сценарий и остаток. Для UI открой /design/demo/index.html того же worktree: общий компонент и его пример меняются в одной ветке/задаче; демо-runtime не подключается к рабочим формам.

По «выкладывай» тот же агент дожидается конца предыдущей публикации, получает свежий main, объединяет со своей веткой и адресно проверяет результат. Если показанное поведение заметно изменилось, показывает разницу до слияния. Затем публикует PR и сливает через GitHub в main; при изменении base снова обновляет и проверяет. Дожидается автодеплоя, сверяет commit/image_id через /_ops.php, проверяет вход и опубликованный сценарий, обновляет WORK.md и завершает задачу. После сбоя публикации задача не закончена. Непроверенные кандидаты в main не сливать. Остальные агенты продолжают локальную работу.
