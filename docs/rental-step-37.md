# Шаг 37. Передача задач в MAX

Рабочая база для проверки — отдельная учебная копия от `1d8fb1a`, PHP на 8997, MySQL на 43293. На Windows открыт [вход с пятью ролями](http://127.0.0.1:8997/login) и [Витрина](http://127.0.0.1:8997/design/demo/index.html). Браузерные формы проверены при 950 × 435 px. Новых элементов интерфейса нет.

Просмотры, согласие с уже назначенной финальной проверкой, запись решения по выставленному счёту, повтор команды, неподтверждённая доставка пакета и откат не образуют новую передачу. Отмена, обычное подписание, уведомление об окончании, ответ клиента и карточка контрагента сохраняют свои существующие маршруты. У ответа клиента нет отдельного назначения сотрудника, а у согласования карточки контрагента нет однозначного номера договора. Состояния календаря, проверки банковских данных и спорные расчёты сами по себе назначения не создают.

## Разовая живая проба после отдельного поручения

Подготовлен [черновик УЧ-MAX-37](http://127.0.0.1:8997/rental/contract?id=900007) и кнопка «Отправить на согласование» под Раисой. Форма предлагает офис «Учебный офис MAX 37» с периодом 01.12–31.12.2026 и суммой 100 000 ₽. До пробы черновик остаётся в исходном состоянии. Договор 900007 существует в Windows-копии. Серверному допуску нужен отдельно разрешённый учебный эквивалент на Linux/ui и его фактические ID, актор и ключ открытой формы. Текущий Windows-допуск согласований не распространяется на новый шаблон.

Формат сообщения для открытой задачи при нескольких юристах:

```text
Договор № УЧ-MAX-37
Передал: Раиса Шилова
Дальше действует: Юрист
Задача: Проверить договорные документы
```

На первой живой пробе отдельный операторский допуск должен подтвердить учебную карточку, активного сотрудника, событие выше нижней границы, действие `contract.edit` с отправкой из открытой формы и ровно её `command_key`. Утверждается только шаблон `staffHandoff`, версия из каталога, точная группа `ТЕСТОВАЯ` и её привязка, текущая ревизия профиля и хеш хранилища. Прежний операторский инструмент имеет отдельные флаги для установки только этого шаблона и выпуска отдельного приватного допуска. Его не запускали на сервере. Для выбранной команды прежний транспорт не используется даже после неизвестного результата. Для независимых ранее разрешённых уведомлений применяются прежние условия, ключи и сверка.

## Серия учебных передач

У приватного серверного маркера теперь два взаимоисключающих режима. Разовый по-прежнему связывает одну команду. Режим серии связывает явный список пар «ID и номер учебного договора», точный перечень действий, эпоху и нижнюю границу событий, начало и срок действия, профиль MAX, единственную группу `ТЕСТОВАЯ` и версию шаблона `staffHandoff`. Оба режима выключены по умолчанию. Изменение номера требует нового согласованного списка. Заявка на продолжение серии сама по себе не продлевает срок.

После отдельного поручения оператор использует ветку `--enable --staff-handoff-sequence` в `server-workflow-max-setup.php`. На входе приватный JSON с тремя утверждёнными полями `contracts` (объекты `id` и `number`), `actions` (точные строки команд) и `expires_at` (Unix timestamp). Оператор сначала сверяет, что карточки учебные. Утилита проверяет их номера, добавляет текущую эпоху, нижнюю границу, начало, привязку существующего профиля и шаблона и выводит маркер для отдельной установки. Команды установки на сервере не выполнялись.

Для проверки серии выбран только [ММ-37, ID 900006](http://127.0.0.1:8997/rental/contract?id=900006).

| Команда | Переход | Наблюдение на подставном транспорте |
| --- | --- | --- |
| `closing.return-finance` | Наталия возвращает финальную сверку менеджеру | Один вызов, сохранён неизвестный исход. Повтор возвращает тот же результат, старый маршрут для этого события заблокирован |
| `closing.resubmit` | Раиса передаёт исправления конкретному проверяющему, Наталии | Один отдельный вызов, сохранён ответ о принятии. Повтор не создал третьей попытки |

Реальный локальный возврат по [ЦИКЛ-37, ID 900008](http://127.0.0.1:8997/rental/contract?id=900008), возврат юристом `closing.return-legal` по ММ-37, а также свежая передача с несовпадающей эпохой, на нижней границе или после истечения допуска вызовов не добавили. При совпадении карточки и действия истечение срока останавливает выбранный маршрут, без переключения на старый. Исторические статусные уведомления вне списка фактических передач сохраняют прежние условия.

Серия использует общую блокировку провайдера и интервал адресата, одну попытку на событие и прежний запрет при незавершённой заявке `pending`. Неизвестный результат остаётся на сверке и закрывает повтор своего события. Следующая независимая передача использует собственную квитанцию. Повторного обхода событий нет. Если почтовую доставку подтверждает фоновый SMTP, переход сохраняется в истории пакета, но фонового вызова MAX здесь нет. Отдельный способ доставлять такие фоновые переходы ещё не подключён. Подтверждённое выполнение в браузерном журнале операций пользуется общим путём после коммита.
