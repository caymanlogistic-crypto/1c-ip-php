# 052 — незавершённый черновик договора

Миграция меняет только nullable contracts.party_id и добавляет CHECK: отсутствие контрагента допускается в draft/returned/cancelled. FK сохраняется; строки, документы и деньги не преобразуются. Пользователь разрешил подготовку и проверку в отдельной локальной копии. Общая БД не менялась.

Локально применён только зафиксированный 052_contract_optional_draft_party.sql к ipphp_task_contracts. Перед применением сохранены DDL и число строк в .local/draft-migration-before.json; число договоров не изменилось. SHA256 и имя записаны в schema_migrations. Полный bin/migrate.php не запускался: несвязанные pending-миграции и admission не включались.

Перед будущей публикацией требуется отдельное согласованное применение этой миграции к целевой БД со сверкой DDL, версии MySQL, количества строк и резервом. Обычный workflow миграции не запускает. Сначала совместимая схема, затем код; проверить пустой и неполный черновики, повторное открытие и отказ в незаполненном согласовании.

Возврат схемы к NOT NULL допустим лишь когда SELECT COUNT(*) FROM contracts WHERE party_id IS NULL возвращает 0: затем DROP CHECK contracts_party_for_workflow и MODIFY party_id BIGINT NOT NULL. Не удалять черновики и не назначать им фиктивных контрагентов ради возврата. Если пустые проекты уже существуют, сохранять расширенную схему и код чтения неполных проектов: старый код может скрывать такие строки из реестров. Откат образа не откатывает введённые данные.

Адресная проверка в отдельной тестовой БД: APP_CONTRACT_DRAFT_TEST=1 php tests/contract-drafts.php. Тест требует ipphp_task_* и выполняет новые команды внутри откатываемой транзакции; для ожидаемого отказа использует SAVEPOINT, поскольку вложенный DB::transaction не создаёт его автоматически. Внешние отправки не запускаются.
